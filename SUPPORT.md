# Support

## Getting help

Use GitHub Discussions, when enabled, for design questions and usage help. Use GitHub Issues for reproducible defects or narrowly scoped feature proposals.

Before opening an issue:

1. Read the [Model Specification](docs/MODEL_SPECIFICATION.md) and [API Reference](docs/API.md).
2. Search existing issues and release notes.
3. Reproduce the behavior against the latest `main` commit with the bundled synthetic reference scenario.
4. Remove all real-site, customer, credential, and operational information.

A useful report includes the operating system, Python or container version, commit SHA, command, sanitized input, expected result, actual result, and relevant logs. Never attach proprietary facility data.

## Scope of support

Community support is best effort. There is no guaranteed response time, uptime commitment, safety certification, engineering sign-off, or warranty. Questions asking the maintainers to validate a real electrical design, switching plan, protection scheme, or compliance position are outside the project's scope.

Security issues must follow [SECURITY.md](SECURITY.md), not the public issue tracker.
